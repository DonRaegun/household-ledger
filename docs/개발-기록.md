# 개발 기록

가계부를 만들면서 버전마다 **어떤 문제가 있었고, 어떤 방법을 생각했고, 무엇을 골랐는지**를 남긴 기록이에요. 사용법은 [README](../README.md)를 보세요.

버전 번호는 안드로이드 앱의 릴리스 번호(`가계부 2.13`)예요. 태그는 `build-<versionCode>`라서 `2.13`은 `build-24`예요. 날짜는 모두 2026년 11월이고, 11월 2일에 시작해서 며칠 동안 빠르게 이어 만들었어요.

## 처음부터 지킨 원칙

- **내 데이터는 내 폰에만.** 서버, 로그인, 광고가 없어요. 내역은 `localStorage`에만 저장해요.
- **단순하게.** 기능을 늘릴 때마다 화면이 복잡해지는지 먼저 따져요. 그래서 설명은 접고, 드물게 쓰는 건 한 단계 안으로 넣어요.
- **알림은 읽되 함부로 넣지 않아요.** 금액, 가맹점, 시각이 모두 확실한 새 결제만 자동으로 넣고, 나머지는 확인을 받아요. 자동으로 넣은 것은 되돌릴 수 있어요.
- **개인정보를 코드와 기록에 남기지 않아요.** 문자·알림 예시와 테스트는 모두 가짜 값이에요.

## 1.0 ~ 1.3: 웹 가계부를 앱으로

**문제**
- 웹 가계부는 입력하기가 귀찮았어요. 결제할 때마다 금액과 가맹점을 손으로 넣어야 했어요.
- 웹은 폰의 알림을 읽을 수 없어요.

**생각한 방법**
- 문자 내용을 붙여넣어 읽는 방법(웹에서 가능)은 만들었지만 여전히 손이 가요.
- 알림을 자동으로 읽으려면 안드로이드의 알림 접근 권한이 필요해서, 같은 웹 코드를 Capacitor로 감싼 앱으로 가기로 했어요.
- 처음부터 앱과 웹을 따로 만들면 화면이 두 벌이 되니, **웹 화면은 하나만 두고 앱은 껍데기와 알림 읽기·업데이트·파일 내보내기 같은 자바 기능만** 맡기기로 했어요.

**고른 방법과 이유**
- 알림 수신 서비스는 결제·입출금 알림만 골라 폰 안 보관함에 쌓고, 앱을 열 때 웹 쪽이 가져가서 가계부에 넣어요. 상시 실행하지 않아도 알림이 올 때만 시스템이 깨워 줘요.
- 카드·계좌 번호와 가려진 이름은 저장하기 **전에** 지워요.
- 앱 안 업데이트는 플레이 스토어 없이, 공개 저장소의 GitHub Releases에서 새 버전을 확인하고 내려받아 설치 화면까지 열어 줘요(설치는 사용자가 눌러요).

**겪은 일**
- 웹뷰는 `<a download>`를 처리하지 못해서 백업과 CSV를 받을 수 없었어요. 파일을 캐시에 쓰고 공유 창으로 넘기는 플러그인을 만들었어요.
- JDK 25에서는 Gradle이 `Unsupported class file major version`으로 실패해서 JDK 21을 썼어요.
- 입금·출금 알림도 모으기 시작했어요(1.2). 출금은 지출(계좌이체), 입금은 수입으로 넣고, 카드대금처럼 카드 내역과 겹칠 수 있는 출금은 확인을 받게 했어요.
- 1.3: 요약 카드에서 지출을 눈에 띄게 했어요.

## 1.4 ~ 1.6: 읽기 좋게, 중복 없이

- **1.4 달력:** 토요일은 파랑, 일요일과 공휴일은 빨강. 공휴일은 규칙으로 계산하고(대체공휴일 포함), 임시공휴일·선거일은 계산할 수 없어 알려진 날짜만 표에 넣었어요.
- **1.5 목록:** 날짜별 합계를 넣고, 제목을 카테고리가 아니라 가맹점으로 바꿨어요. 알림으로 들어온 내역은 카테고리가 대부분 기타라서 메모(가맹점)가 알아보기 쉬웠어요.
- **1.6 중복:** 같은 결제인데 문자와 카드 앱 알림이 1~2분 차이로 따로 와서 두 번 들어갔어요.
  - 생각한 방법: (a) 시각이 정확히 같은 것만 같은 결제로 보기 (b) 같은 금액이면 무조건 합치기 (c) 같은 금액이고 몇 분 안이면 합치기.
  - 고른 것: (c). 2분 안의 같은 금액은 한 건으로 봐요. 대신 같은 금액을 2분 안에 정말 두 번 결제하면 한 건으로 합쳐지는 한계가 있어요.
  - 같은 날 같은 금액의 고정지출이 이미 들어가 있으면 알림이 와도 새로 넣지 않고 합쳐요.

## 1.7 ~ 2.0: 구조를 정리하고 안전하게

- **1.7 코드 나누기:** `app.js` 한 파일이 1,500줄이 됐어요. 빌드 도구를 쓰지 않고 `<script>`로 차례로 불러오는 기능별 파일로 나눴어요.
  - 처음 나눌 때는 코드를 한 줄도 바꾸지 않고 잘라 붙였고, 원래 줄이 모두 들어 있는지 확인했어요.
  - 화면이 없는 파일(`core`, `sms`, `holidays`)은 브라우저 없이 시험할 수 있게 하고, 가짜 예시로 `npm test`를 만들었어요.
  - 자동 백업: 일주일마다, 내역이 바뀌었을 때만 다운로드 폴더에 백업 파일을 남겨요(최근 8개). 알림 접근이 켜져 있는데 오래 알림이 없으면 절전 설정을 확인하라고 알려요.
- **1.8:** 카테고리를 드롭다운 대신 버튼으로 한 번에 고르게 했어요. 홈 화면을 정리했어요.
- **1.9:** 새 아이콘. 위쪽 연·월을 눌러 원하는 달로 바로 이동해요.
- **2.0:** 뒤로가기와 바깥 터치로 창을 닫고, 창이 열린 동안 뒤 화면이 스크롤되지 않게 했어요.

## 2.1: 토스 알림이 안 들어와요

**문제:** 토스 결제 알림은 제목에 금액(`32,420원 결제`)이 있고 본문에는 `카드 | 가맹점`만 있어요. 그때까지의 읽기 규칙은 본문에서 금액을 찾아서, 금액이 없다고 보고 버렸어요.

**생각한 방법:** (a) 토스 전용 규칙을 따로 만들기 (b) 제목과 본문을 합쳐서 읽기.

**고른 방법:** (b). 제목에 금액이 있을 때(또는 은행 단어가 있을 때)는 제목과 본문을 합쳐서 같은 규칙으로 읽어요. 형식마다 규칙을 늘리는 것보다 합치는 쪽이 다른 앱에도 통해요.

**일부러 하지 않은 것:** 외화 결제 알림(원 단위 금액이 없음)과 토스의 자동이체 알림은 읽지 않아요. 잘못 읽어 넣는 것보다 직접 입력하는 게 낫다고 봤어요.

## 2.2: 앱 안 업데이트가 "받을 수 없는 주소예요"

**문제:** 저장소 이름(소유자)을 바꿨더니, 앱이 내려받을 주소를 믿어도 되는지 검사하는 허용 목록에 옛 이름만 있어서 업데이트가 막혔어요.

**고른 방법:** 허용 목록에 새 이름과 옛 이름을 모두 넣었어요. 이 버전이 깔리기 전의 앱은 업데이트 기능 자체가 막혀 있어서, **이번 한 번은 직접 설치해야** 했어요. 앱을 파일로 나눠 주면 새 버전이 나올 때마다 다시 올려야 해서, Releases 페이지 링크를 공유하는 쪽이 낫다고 정리했어요.

## 2.3: 카카오뱅크 입금 알림

**문제:** 제목에 금액, 본문에 이름과 `입출금통장`이 있는 입금 알림이 입금으로 들어오지 않았어요. `입출금통장`의 `출금`을 방향 단어로 읽는 문제도 있었어요.

**고른 방법:** 방향을 판단할 때 `입출금`, `출금계좌`, `입금계좌`처럼 계좌 이름에 든 단어는 먼저 지우고 읽어요. `A → B` 형식은 받는 쪽과 보내는 쪽을 구분해서 읽어요. 알림 토스트는 좌우로 밀어 닫게 했어요(위아래 스크롤과 구분하려고 가로 방향만).

## 2.4: 새 디자인

**문제:** 색감도 디자인도 너무 단순해서 마음에 들지 않았어요.

**생각한 방법:** 방향을 정해 놓고 시작하려고 선택지를 물었어요. 어두운 프리미엄 느낌으로 가고, 밝은 모드는 따로 만들지 않고 **폰의 설정을 따라가게** 하기로 했어요.

**고른 방법:** 색을 CSS 변수로 모아 밝은 모드와 어두운 모드를 같은 구조로 만들었어요. 폰 설정(다크 모드)을 따라가요. 안드로이드의 상태바와 내비게이션 바 색도 맞췄어요. 홈은 요약 한 장, 통계에는 지난달과의 비교, 설정은 묶음별로 정리했어요.

## 2.5: 검색과 지난달 비교

- 전체 기간에서 가맹점, 카테고리, 금액, 날짜(`2026-11`)로 찾는 검색을 넣었어요.
- 통계에 카테고리별로 지난달보다 얼마 늘었는지, 가장 많이 달라진 곳이 어딘지 보여 줘요. 진행 중인 달은 지난달 **같은 날짜까지만** 비교해요(안 그러면 이번 달이 항상 적어 보여요).
- 취소 알림이 어떤 내역을 지울지 확인 창에서 보여 줘요.

## 2.6 ~ 2.8: 화면 모드, 돌려서 고르기, 설정, 업데이트 흐름

**2.6**
- 화면 모드를 자동/밝게/어둡게 중에 고를 수 있게 했어요. 문제는 안드로이드의 상태바·내비게이션 바 아이콘이 **앱의 모드가 아니라 폰의 모드**를 따라간다는 점이었어요. 폰은 밝은데 앱만 어둡게 하면 어두운 바탕에 어두운 아이콘이 되어 안 보여요. 그래서 모드를 네이티브로 알려 주는 `ThemeBars` 플러그인을 만들어, 밝은/어두운 조합을 에뮬레이터에서 모두 확인했어요.
- 시각, 날짜, 고정지출의 매달 며칠을 안드로이드 기본 선택 창 대신 **돌려서 고르는 창**(갤럭시 알람 느낌)으로 바꿨어요.
- 내역을 날짜별로 접고 펼치는 기능, 부드러운 전환 효과를 넣었어요(2.11에서 다시 바뀌었어요).

**2.7:** 결제일·사용 시작일·알림 시점도 돌려서 고르게 하고, 체크박스를 토글 스위치로 바꿨어요. 알림 접근과 "확인 없이 자동으로 넣기"가 한 칸에 섞여 있어서 따로 나눴어요.

**2.8 업데이트 버튼을 두 번 눌러야 해요**
- 문제: 첫 번째 누름은 "새 버전이 있어요"만 띄우고 설치는 시작하지 않았어요. 두 번째에야 설치 화면이 나왔어요.
- 원인: "출처를 알 수 없는 앱 설치" 권한이 꺼져 있으면 시스템 설정 화면이 열려요. 사용자가 켜고 돌아와도 앱은 이어서 설치하지 않았어요.
- 재현: 에뮬레이터에서 권한을 거부시켜 같은 현상을 만들었어요.
- 고친 방법: 권한이 있는지 먼저 확인하는 기능(`canInstall`)을 추가하고, 설정을 다녀온 뒤 앱이 다시 보이면 설치를 **자동으로 이어서** 하게 했어요.

## 2.9 ~ 2.10: 읽기 좋게, 그리고 과한 효과 빼기

**2.9**
- 글이 너무 붙어 있다는 의견에 줄 간격과 여백을 넓혔어요.
- 금액을 입력하면 아래에 작고 옅게 한글로 읽어 줘요(`12,345` → `일만 이천삼백사십오원`). 0을 하나 더 넣는 실수를 줄여요.
- 연별 월별 지출을 막대에서 **꺾은선 그래프**로 바꿨어요. 선이 왼쪽에서 오른쪽으로 그려져요.
- 원 그래프를 바꿀 때 조각이 뚝뚝 끊겨 보였어요. 조각마다 따로 지연을 주던 CSS 애니메이션을 버리고, 이전 모양에서 새 모양으로 **한꺼번에 이어서 바뀌는 방식**(프레임마다 계산)으로 바꿨어요.
- 내역 추가의 "더보기"가 가로로 공간을 차지하며 접히던 것을 높이 전환으로 부드럽게 했어요.
- "소비 성격"이라는 말이 어색해서 "소비 평가"로 바꿨어요.
- 위쪽 연·월 창에서 연도를 누르면 연도 목록이 나와요.

**2.10**
- 원 그래프를 누르면 조각이 반짝이는 효과가 지나치다는 의견에, **색이 강조되는 정도만** 남겼어요(굵어지고 나머지는 흐려져요).
- 연·월 창에서 좌우로 밀면 연도가 넘어가요. 이때 **뒤 화면의 월이 같이 넘어가던 문제**는, 열린 창이 하나라도 있으면 뒤 화면의 밀기를 막도록 고쳤어요.
- 요약 카드 오른쪽 위에 번지던 빛 무늬를 없앴어요. "AI가 만든 티가 난다"는 의견을 받아들였어요. 이후에도 꾸밈은 먼저 빼는 쪽으로 판단해요.

## 2.11: 내역·설정 단순화, 통계 카드

**내역: 오늘만 펼치기**
- 문제: 글이 많아서 읽기 어려웠어요. 날짜별 접기도 날마다 눌러야 해서 번거로웠어요.
- 고른 방법: 오늘 내역만 항상 펼쳐 두고, 나머지는 **"이전 내역 보기"** 창에서 그 달 것만 봐요. 접기·펼치기와 "모두 접기" 버튼은 없앴어요.

**+ 버튼과 화면 모드 전환의 번뜩임**
- + 버튼은 파란 빛이 번지는 그림자를 없애고 얇은 그림자만 남겼어요.
- 밝게/어둡게를 바꿀 때 번뜩이던 원인: 요소마다 따로 색이 바뀌는데, 그라데이션 배경은 서서히 바뀌지 못하고 한꺼번에 바뀌어서 어긋났어요. 요소별 전환 대신 **화면 전체를 한 장처럼 크로스페이드**하는 방식(View Transitions)으로 바꿨어요. 지원하지 않는 환경에서는 바로 바뀌어요.

**설정 단순화**
- 작은 제목, 한 줄 항목, 긴 설명은 한 군데에 접어서 보여 주는 구조로 다시 짰어요. 데이터 관리의 큰 버튼 3개는 한 묶음의 목록으로 바꿨어요.
- **고정지출을 설정에서 내역 탭으로** 옮겼어요. 설정에 목록이 길어져서 지저분해졌고, 확인은 내역 탭에서 하고 수정만 설정에서 하는 구조도 어색했어요. 내역 탭 요약 카드 아래의 한 줄을 누르면 창이 열려요.

**통계 카드**
- 위쪽 카드를 옆으로 밀면 주별 지출(월별 보기) 또는 월별 지출(연별 보기) 꺾은선과 지난 기간 비교가 나와요. 한 달을 7일씩 끊어 1주차, 2주차로 계산해요.
- 그래프의 점을 누르면 그 달(주)의 금액만 떠요.
  - 생각한 방법: 점을 누르면 그 달로 이동, 길게 누를 때만 금액 표시, 짧게 눌러 금액 표시.
  - 고른 것: 짧게 눌러 표시. 길게 누르기는 알아채기 어렵고, 안드로이드에서 진동이나 글자 선택과 겹치고, 옆으로 미는 카드와도 충돌해요. 이동은 없앴어요.
- 월별과 연별에서 카드 높이와 위치가 달라서 전환할 때 아래 내용이 튀었어요. 같은 높이로 맞췄어요.

## 2.12: 카테고리를 큰 묶음으로

**문제:** 통계에 색이 너무 많아서 지저분해 보였어요. 카테고리가 10개였고 색도 서로 어울리지 않았어요. 또 내역에서는 점 하나뿐이라 카테고리를 글로 읽어야 했어요.

**생각한 방법**
1. 색을 더 어울리게 바꾸기(밝기와 진하기를 맞춘 색).
2. 카테고리마다 다른 아이콘을 내역 왼쪽에 놓기.
3. 비슷한 카테고리는 같은 색으로 묶기. 이때 두 가지가 있었어요.
   - A. 도넛과 목록을 **큰 카테고리**로 그리고, 누르면 아래에 작은 카테고리가 펼쳐지기
   - B. 조각은 그대로 두고 같은 묶음은 같은 색 계열의 진하고 옅은 색으로 칠하기

**고른 방법:** A. B는 같은 색 조각 둘이 도넛에서 한 덩어리로 보여서 어디까지가 어느 카테고리인지 알기 어려워요. A는 색이 5가지뿐이라 가장 차분해요.

**결과**
- 큰 카테고리 5개: 먹고 마시기(식비·카페), 교통, 쇼핑/여가(쇼핑·문화/여가), 고정비(고정비·구독), 기타(의료·경조사·기타).
- 작은 카테고리 10개에는 모두 다른 아이콘이 있고, 색은 큰 카테고리마다 하나예요.
- 주거/통신과 보험은 "고정비"로 합쳤어요. 쇼핑과 문화/여가는 한 번 합쳤다가 다시 작은 카테고리로 나눴어요(큰 카테고리는 하나로 유지).
- 옛 이름으로 저장된 내역과 백업 파일은 읽을 때 새 이름으로 바꿔요. 한 번 바꾸면 되돌리지 못하니 백업을 권해요.
- 자동 분류에 통신, 보험, 구독 서비스, 영화 같은 단어를 더했어요. 이전에는 5개 카테고리만 자동으로 정해졌고, 나머지는 거의 "기타"로 들어갔어요.

**고정지출 입력을 단순하게**
- 문제: 고정지출을 추가할 때 카테고리 8개 중에서 골라야 했어요. 그리고 "고정지출"(매달 자동으로 내역을 넣어 주는 기능)과 "고정비"(카테고리)라는 이름이 비슷해서 헷갈렸어요.
- 생각한 방법: 일반 지출에서 고정비 카테고리를 없애고 고정지출 안에서만 쓰기.
- 안 고른 이유: 고정지출이 넣은 내역도 카테고리가 필요해서 결국 숨은 카테고리가 생겨요. 같은 월세인데 고정지출로 들어오면 고정비이고 알림이나 직접 입력이면 기타가 되어 통계가 어긋나요.
- 고른 방법: 입력 화면만 **고정비 / 구독** 두 칸으로 줄였어요. 일반 지출의 카테고리 목록은 그대로예요.

## 2.13: 이전 내역 버튼과 구독

- **이전 내역 버튼:** 그 달에 오늘 내역만 있을 때 버튼이 숨어서 "지난 내역이 어디 갔냐"는 질문이 나왔어요. 이제 그 달에 내역이 있으면 항상 보이고, 누르면 **그 달 내역 전체**를 보여요. 지난달 이전 내역은 월을 옮겨서 봐요(다른 달까지 한 화면에 쌓으면 길어져서 달 단위로 두었어요).
- **구독:** 구독을 문화/여가에 넣던 방식을 바꿔 **작은 카테고리 "구독"**을 만들었어요(큰 카테고리는 고정비 안). 월세, 통신, 보험처럼 꼭 내야 하는 돈과 해지할 수 있는 구독을 나눠 보고 싶었어요. 이미 구독으로 등록한 고정지출과 그 내역은 앱을 열 때 한 번만 구독으로 옮겨요.
- **알림이 먼저 오는 경우:** 구독 결제 알림이 고정지출보다 먼저 들어오면 이름을 못 맞혀 "기타"로 들어갔고, 나중에 고정지출과 합쳐져도 기타로 남았어요. 이제 합칠 때 "기타"였으면 고정지출의 분류를 따라요(직접 바꾼 카테고리는 건드리지 않아요).

- **README 화면 이미지:** 가짜 데이터와 고정한 시계(2026-11-25)로 헤드리스 크롬에서 다시 찍었어요. 찍다가 `[알림 …]` 도착 시각 줄이 ●로 시작하는 문자와 따로 잘려 "읽지 못한 문자 1건"으로 나오는 작은 오류를 찾아, 시각 줄은 본문 시각으로 세지 않게 고치고 시험을 추가했어요(다음 릴리스에 들어가요).

## 개발하며 배운 점

- **먼저 원인을 확인하고 고쳐요.** 업데이트 버튼은 에뮬레이터에서 권한을 거부시켜 같은 현상을 만든 뒤에야 고쳤어요. 번뜩임도 어떤 요소가 따로 바뀌는지 파악한 다음에 방식을 바꿨어요.
- **화면 효과는 빼는 쪽이 더 어려워요.** 반짝임, 번지는 빛, 많은 색은 처음엔 예뻐 보이지만 의견을 받으면 대부분 걷어냈어요.
- **이름이 비슷하면 헷갈려요.** 고정지출(기능)과 고정비(카테고리)처럼, 기능과 분류는 이름을 다르게 하거나 입력 화면에서 구분해야 해요.
- **한 번 바꾸면 되돌릴 수 없는 일은 백업부터.** 카테고리 합치기처럼 데이터 이름을 바꾸는 변경은 읽을 때 변환하고, 시험으로 확인해요.
- **형식마다 규칙을 늘리지 않아요.** 토스, 카카오뱅크 같은 알림 형식이 늘어날 때마다 전용 규칙을 만드는 대신, 제목과 본문을 합치고 방향 단어를 정리하는 공통 규칙으로 풀었어요.

## 아직 남은 한계

- 외화 결제 알림과 카드대금·자동이체 같은 일부 알림은 읽지 않아요.
- 카드는 한 장만 설정할 수 있어요. 예산 기능은 없어요.
- 본인 계좌 사이의 이체(예: 토스 → 은행 계좌)는 출금과 입금이 각각 들어가서 수입이 한 번 잡혀요.
- 업데이트 파일의 무결성(체크섬)은 확인하지 않아요. 주소는 허용 목록으로만 걸러요.
- 디버그 서명 키로 만든 APK라서, 다른 PC에서 빌드한 APK는 덮어 설치가 안 돼요. 서명 키를 따로 보관해야 해요.
- 폰(갤럭시)에서의 실제 동작은 계속 확인이 필요해요. 특히 알림 수신과 절전 기능의 관계, 화면 전환 효과가 그래요.
- 자동 UI 테스트는 없고, 화면은 브라우저와 에뮬레이터에서 직접 확인했어요.
